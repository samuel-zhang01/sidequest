# RUN/HACK event pack

This folder separates organiser requirements from product strategy so that an
idea or team assumption is never mistaken for an event rule.

## Contents

| File | Purpose |
| --- | --- |
| [`event-requirements.md`](event-requirements.md) | Rules, schedule, eligibility, submission fields, scoring, prizes and event preparation. |
| [`event-logistics.md`](event-logistics.md) | Venue, required apps, sponsor-credit setup, packing list, facilities and event-day support. |
| [`sponsor-challenges.md`](sponsor-challenges.md) | Healf, voice, GTM, cloud and texting challenge briefs. |
| [`product-ideas.md`](product-ideas.md) | Ranked, architecture-aware concepts and deliberately deferred ideas. |
| [`judging-criteria.md`](judging-criteria.md) | SideQuest-specific scorecard, demo plan and pitch rehearsal. |

## Source priority

When sources conflict, use this order:

1. Instructions given by organisers at check-in.
2. [How The Hack Works](https://shore-dingo-75a.notion.site/How-The-Hack-Works-3c8c9ef714788041b796ef14bccd438a).
3. [RUN/HACK public event page](https://www.therunninghackathon.com/).
4. [Preparation guide](https://shore-dingo-75a.notion.site/How-to-Prepare-for-London-s-First-Running-Hackathon-3c8c9ef7147881d49039ff6c9d14a9ea).
5. Repository planning notes.

The source pages are live documents. This pack was reconciled on 2026-08-29;
confirm last-minute changes at check-in.

## Critical eligibility warning

The organiser brief says existing projects and repositories are disqualified:
everything must start from nothing on the day, and organisers may inspect
first-commit evidence and agent session history. This repository is therefore
useful as architecture and pitch research, but **must not be submitted or
copied into an entry unless an organiser explicitly confirms that it is
eligible**.
